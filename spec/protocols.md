# 意思決定・証拠・継続改善

## 意思決定

1. Goal・Context・合意の版を指定する。影響が重大、不可逆、未合意、または事業・運用・レビュー規範を変える判断は重要と判定する。境界が不明なら重要として扱う。
2. 何もしない案を基準に置き、選択肢ごとに因果仮説、期待効果、費用、行動するリスク、不作為時の損失、迷い、反証と再評価条件を比較する。
3. 独立レビューには対象と最低限の前提、Context付きレビューにはGoal・Context・関連判断を渡す。後者は責任AIと別企業のモデルを使う。企業名は同一企業を判別できる表記に揃え、実行前に取得した各レビューの記録を証拠として参照する。企業名の別表記やレビューの真正性は意味検査で確認する。共有権限と渡した範囲を残す。レビュー依頼と作業委任には別々の権限を適用し、委任には責任者と受入条件を定める。
4. 責任AIが指摘ごとに根拠、採否、残存リスクを記録する。反対意見で判断が変わり得る場合は追加証拠を得るか相談する。追加レビューは期待価値が費用を下回れば切り上げる。必須レビューが利用不可なら未実施を記録し、当該判断による実行を保留する。人間に提出する提案と模擬検証は許可範囲で進める。
5. 合意が必要なら、調査、候補、推奨、費用、リスク、不作為時の損失を示し、承認者、対象版、範囲、期限を記録する。無回答の間は保留する。
6. 実行後は予測との差を仮説、実行、測定、外部要因に分け、Goalへの寄与を判定する。証拠不足なら未判定を記録する。

新しい証拠で重要な判断の推奨案や主要な前提が変わった場合は、以前のレビューが扱った案・前提と照合する。影響を受けない指摘は根拠を添えて引き継ぎ、変更の影響を受ける必須レビューは、変更後の案を対象に実行前に取り直す。旧レビューと再確認の範囲を記録し、待機中も現行権限内で独立して行える調査や比較を続ける。

指摘ごとの裁定は、判断記録の「裁定」から、元の指摘、採用・見送り・保留の理由、その判断を支えた証拠ID、残存リスクをたどれるようにする。指摘や裁定を別の記録に置く場合は、証拠台帳に参照先を登録し、判断記録の「根拠」から参照する。

## 証拠と測定
通常の計画が成立しない場合は [異常系と反証の検証](exception-validation.md) を適用する。

証拠は出典、取得時刻、対象、方法、観測結果、制約を再確認できる資料とする。一次性、利害、独立資料との整合、対象時点での鮮度、再計算または追試の可否を確かめる。信頼性とGoalへの関連性を別々に判定する。矛盾する根拠も保全し、時期や対象の差を調べる。結論を変える不確実性が残るなら保留する。模擬データは手順の検証や仮説の検討に使う。実運用で実行可とする判断には、遷移時点までに取得した資料または実測を根拠に含める。実行後に得られた資料は事後評価に用いる。根拠が当該判断を実質的に支えるかは意味検査で確認する。

施策前に基準値、成功・失敗条件、観測対象、期間、予算、撤退条件を定め、必要な計測を整える。代理指標は因果仮説と崩れる条件を記録する。反実仮想には対照、時差、比較可能な過去、仮定付き推定から選び、偏りを明示する。並行施策は時期や対象を分けるか、効果を識別できる根拠を示す。閾値改定時は旧条件での結果も残し、必要な再合意を得て次の評価に適用する。

測定方法の変更をまたいで比較する場合は、同じ対象と期間を両方式で測った記録などから、方式による差と補正の不確実性を見積もる。元の観測値と補正方法を残し、補正を適用できる対象・期間を示す。補正後の値の範囲が判断の境界をまたぐ場合や、補正を適用できる根拠がない場合は、その比較による判定を保留する。

## 継続改善

- 運用時は内部品質と、法令、費用、インフラ、市場、社会、技術、モデルなどの外部変化を観測する。対象、出典、頻度、担当を記録する。変化が閾値に達したら、影響するContext、非機能要件、判断を再評価する。周期変動では開始と解除の閾値を分ける。
- Goalの進捗、施策と計測、判断とレビューの精度を見直す。判断を維持する場合も再評価日、反証条件、残存リスクを更新する。追加調査の期待効果が低い外部要因は限界を記録して観測に戻す。
- レビューの見逃し、誤指摘、費用、引継ぎで失った情報からFoundationの改善案を作り、旧サンプルとの互換性と移行条件を検証する。両立しない規範は適用範囲と合意事項を示す。人間がPRで判断する。明示された委任がある場合、責任AIは委任条件をPRの検証記録に残し、検証したコミットを指定してマージする。Goal・合意済み要件・予算・許容リスクの変更は、委任条件に含まれない限り人間に相談する。必須レビューの制約と実施状況を記録し、レビューを実施できない場合に進める範囲は人間の指示に従う。

基礎文書の未決事項は、今回の提案だけで合意済みにはならない。重要性の閾値、代理指標の最低条件、無応答時の権限、委任および専門家確認の境界、既存案件への版適用は確認事項とする。長時間稼働、外部レビュー、定期通知は実行環境の能力に依存する。

経済性を評価するときは、売上、直接費、人件費換算の根拠を記録する。意思決定が変わる程度に単価・工数・外部費用が不確かなら、範囲を変えて再計算し、判定が変わる境界を示す。

## 検証から残す成果

案件固有のシナリオ、入力、数値、実行記録は検証に使う。Foundationに残す成果は、別の案件でも手順を再現できる抽象度にする。契約例や評価手順に加え、判断基準、反例、比較方法、改善理由など、検証に必要な形式を選べる。

コミット候補は、検証で判断を変えた条件を特定し、固有の名称や値を取り除いても同じ判断を再現できるか確かめる。閾値は案件の合意を入力とし、判定が変わる条件を示す。自動検証に数値が必要な場合は、境界を検査するための合成値を使う。固有の証拠から一般化した範囲と、一般化できなかった条件を記録する。

### Foundationの定期レビューの取り込み

改善サイクルの区切りで、提出済みのClaudeレビューが `.claude/review-*.md` にあるか確認する。添付先が作業ブランチの場合は、そのブランチも確認する。新着がなければ、返信や提出を待たず自己検証と改善を進める。新着があれば対象コミットと現行仕様を照合し、再現できる指摘を次の改善に取り込む。提出がない時点ではClaudeレビューを未実施として記録する。この運用はFoundation自身の定期レビューに適用する。
