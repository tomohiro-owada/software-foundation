# 実行契約と状態遷移

責任AIは各遷移で時刻、前後の状態、理由、根拠IDを追記する。Goal・Context・合意は版で参照し、訂正時は旧版を保全する。

| 状態 | 入力・事前条件 | 出力・事後条件 | 出口の検証と遷移 |
| --- | --- | --- | --- |
| 準備 | 人間の課題、業務の現状 | Goal、対象者、成功条件、Context、制約、未知 | 判断を最も変える質問を一度に一つ聞く。開始条件が揃えば開始 |
| 開始 | 成熟度、権限と制約 | 責任者、能力、最初の次手、連絡時期 | 責任AIが開始可否を記録し、可なら調査、不可なら準備へ |
| 調査 | Goal・Context、権限 | 要件、候補、未知リスク、比較の証拠 | 行動と不作為を比較できれば意思決定へ |
| 意思決定 | 候補、根拠、測定計画 | 判断仮説、レビューへの処置、採用案、合意 | 必須レビュー、権限、測定、撤退を確認して実行へ。観測だけなら運用へ。不足は調査へ |
| 実行 | 採用案、上限、停止条件 | 操作、費用、副作用 | 実状態を照合し検証へ。失敗時は失敗へ |
| 検証 | 操作結果、測定計画、観測 | 成果物の適合とGoalへの寄与 | 適合すれば運用へ。欠陥は実行、仮説や測定不足は調査または改善へ |
| 運用 | 観測計画、責任者、次回日時 | 内外の変化、評価結果、異常通知 | 閾値到達または予定日で改善へ。維持時は観測を続ける |
| 改善 | 評価・外部変化・過去の判断 | 更新案、再評価理由、次回条件 | 合意内なら調査へ。変更なら相談待ちへ。維持なら運用へ |
| 失敗 | 失敗工程、診断、実状態 | 復旧、再試行、中断の判断 | 副作用と再実行の安全性、回数、予算を照合して失敗元へ。前提不足は調査へ |
| 相談待ち | 権限外・重大リスクと提案 | 相談先、応答期限、合意または保留 | 人間の応答を記録して再開へ。無回答時は既存権限内の独立作業を続ける |
| 中断 | 停止理由と作業状態 | 引継ぎ記録と再開条件 | 条件成立後に再開へ |
| 再開 | 引継ぎ記録と再開根拠 | 現状態、期限・合意・副作用の再確認 | 妥当なら記録した復帰先へ。齟齬は調査または相談待ちへ |

開始条件は課題、対象者、成功条件、責任者、権限、上限、重要制約、測定可能性を確認し、未解決の重大リスクを実行範囲から外せること。既存システムでは実際の挙動と業務意図を別々に確かめる。

準備メモは、開始前に案件の作業記録として保存し、引き継ぐ担当者が参照できる場所を示す。質問、回答、その出典または回答者、確認した時点、未確定事項を残す。開始判定では確定した課題・対象者・成功条件をGoalへ、制約と未知をContextへ反映し、準備メモを証拠台帳へ登録し、「出典」に参照先、「取得」に確認時点を記録する。「準備」から「開始」への遷移の「根拠」に、その証拠IDを含める。未確定事項は、開始可否に与える影響を示す。

各作業状態から権限・重大リスクで相談待ち、環境や人間の指示で中断へ移れる。技術的な失敗は診断を添えて失敗へ移す。引継ぎには最後の完了操作、未確定の副作用、入力の版、次手、責任者、復帰先とその事前条件を含める。撤退後も監視責任があれば運用へ移す。監視自体を終える場合は人間の合意と再評価条件を記録して中断する。

再開時は、合意の版が同じでも、次の操作に必要な費用・工数と実際の残予算・提供期限を照合し、成果の見込みが変わる場合は判断を再評価する。旧判断の前提が崩れた操作は保留し、現行の権限と上限で独立して進められ、次の判断に役立つ調査は続ける。

同じ予算や提供枠を別の作業も使う場合は、実行前に確保済みの割当てか、他の作業の確定分を差し引いた残量を確認する。個別の見積もりが上限内でも、合計が上限を超える場合は両方を進めない。照合後に割当てが変わり得る場合は、実行に必要な分を確保してから進めるか、割当てと実行の判断を順に行う。既存の約束を優先し、顧客成果への影響を比べて残りを割り当てる。

割当てが失効したら、その割当てで新たに着手しない。すでに着手した操作の結果が不明な場合は、実際の消費、成立した約束、取消の反映を確認し、未使用と確認できた分だけ再割当てする。確認が顧客の期限に間に合わない場合は、確認期限と責任者を記録し、別枠での提供や受付制限を比較する。

引継ぎの「再開時照合」には、照合時刻、共通の単位で表す必要費用と残予算、必要工数、実際の提供能力を反映した完了見込、提供期限、復帰または保留の判定を記録できる。必要費用が残予算以下、完了見込が提供期限以前でも、他の事前条件が不足すれば保留する。日時と金額の比較は意味検査で行う。旧記録で欄がない場合は根拠を照合し、不足する証拠を未確認として扱う。

模擬記録の「実行」は仮定やデータを使った演習を表す。試算の権限を確認し、重要な実判断が保留ならその状態を維持する。実運用の実行に移る際は、履歴の各実行遷移に `判断ID` を記録する。その判断が実行可であり、参照先の合意が遷移時点に有効で、測定計画が遅くともその時点に確定していることを確認する。旧記録の理由欄に判断IDがある場合は元の記録を保全し、確認できたIDだけを転記する。

Goal・Context・合意の改訂時は、置き換えるレコードを旧版として残し、当時の判断の参照先を維持する。現在の権限で再開する場合は、現行の版を引継ぎに記録する。旧版のGoalや合意がない既存の記録では、`旧Goal` と `旧合意` を省略できる。過去の版が見つからない場合は出典を確認し、推測による復元は行わない。

測定計画を改訂する場合は各計画に `版` を付け、従前の計画を `旧測定` に保存する。実行判断にその時点で採用した `測定版` を記録し、実行時の事前確定条件はその版で照合する。単一計画で版を持たない従来の記録も読み込める。旧記録に版を割り当てる際は、当時採用した計画を確認できた場合だけ判断から参照する。

合意に発効時刻がある場合は `発効` を記録する。実運用の実行遷移は、参照した合意の発効から期限までの範囲内で行う。発効時刻が記録されていない場合は、別の資料で当時の有効性を確認する。期限だけで発効を推定しない。

新規の実運用記録では、判断を実行可に確定した時刻を `実行可確定` に記録する。確定時刻は実行遷移と同時かそれより前とし、判断と必須レビューの根拠は確定時点までに取得したものを照合する。従来の記録で確定時刻がない場合、自動検査は実行時点を根拠取得の上限として扱う。実際にいつ確定したかは元の判断記録を確認する。

合意を撤回した場合は、元の発効・期限と判断の参照を保全し、同じ合意版に撤回が効力を持つ時刻を `撤回` として追記する。撤回時刻以降は、その版での実行や再試行を保留する。すでに実行中なら新しい操作を止め、停止に副作用がある場合は許可済みの安全な措置を確認する。再開する場合は有効な合意を取り直し、影響を受けた判断を再評価する。

発効予定だった合意を発効前に撤回する場合も記録できる。その合意には実行可能な期間が生じない。改訂前の合意をいつまで適用するかは、改訂時に当事者が確認し、期限または撤回時刻を記録する。
