# Software Foundation自身への適用

Goalは、既存のエージェントが事業の判断・証拠・引継ぎを再現できること。既存7文書を保全し、規範と実行記録を追加する案を選んだ。現状維持では事前条件や再開の検査手順が揃わず、専用エンジンは権限外。比較の結果、規範と記録契約を採用した。実運用での有効性と異なる企業のAIレビューは未確認。未決事項は人間の判断対象とする。PRの検証とマージの操作は人間の明示指示により委任された。

## 形式検証

JSON Schema Draft 2020-12と日時形式検査を有効にする。[契約の確認例](contract-run.json)は受理する。同じ記録から重要な判断を必須レビューなしで実行可にした例と、準備から運用に直接移る例を作り、拒否を確認する。

## 意味検査

- 課題が曖昧な場合、判断を変える対象者や工程を一問で特定する。Contextの各制約から品質目標と検証方法を導出する。
- 不作為を含む候補を比較し、決定時のGoal・Context・合意の版、根拠、レビューへの処置を残す。
- 成果物の適合とGoalへの寄与を評価する。稼働時間を費用に含め、仮定を変えて判断が逆転する境界を確認する。外部変化があっても従来の判定条件で再計算し、違う条件を使う場合は次の評価に適用する。
- 中断から戻る際は、入力の版、権限、副作用、次手を照合する。未知の重大リスクや権限外の操作があれば相談待ちにする。

再検査時は、履歴の先頭・連続性・時刻順と末尾の現在状態、IDの一意性と参照先、判断時点のGoal・Context・合意版を確認する。実運用の実行遷移は実行可の判断と突き合わせ、必須レビューの企業差、共有権限、各根拠、測定の事前確定、合意の有効期限を確認する。模擬証拠の実測への流用、予算超過、成功条件の事後変更を確認したら適合を保留する。構造検査だけでは参照先、レビューの真正性、測定の妥当性、因果関係を判定できない。

次に人間が判断するのは、重要判断の境界と別企業レビューの利用方法、案件ごとの評価条件、既存案件に適用する版。自動監視や実顧客での成功は未検証。

## PRと取り込み後の再検証

対象のコミットを固定し、下記の再現手順で検証する。基礎7文書は初回コミット `8ad57cf` の原文と照合し、変更した文書の相対リンクも確認する。原文を取得できない場合は未検証と記録する。

PRの先端コミットを検証し、差分の意味検査を行う。マージを人間から委任された場合は、検証したコミットを指定して取り込む。取り込み後は最新の基準ブランチを取得し、同じ検査を再実行する。失敗時は差分と原因を報告し、修正を次のPRで検証する。別企業レビューの実施状況は検証結果と併記する。

文書の並べ替えでは、本文の欠落、見出し、参照先を照合する。実行契約やスキーマの判定を変える場合は、変更した条件の確認に加え、既存の確認データ一式を再検証する。新しい任意欄を使う例だけでは、その欄を持たない従来の記録が受理されるかを確認できない。

履歴の日時はオフセットを反映した時点で比較する。サンプル検証では、表記上は前後が逆でも順序が正しい履歴を受理し、実際に逆転した履歴と、採用先を一意に特定できない候補IDの重複を拒否する。

引継ぎのGoal・Context・合意の版を現行記録と照合する。版が変わった場合は再開前に影響を再評価する。レビューの根拠も判断本体と同じ証拠台帳で確認し、参照が切れていたら結論の再評価に戻る。

## 異常系の確認

[異常系と反証の検証](../spec/exception-validation.md)を用いて、正常系と同じ判定条件に次の反例を適用する。固有の案件データは不要。変更対象の条件と、判断が変わる境界を再現できればよい。

- 合意期限と同時刻は受理し、期限後は拒否する。事前確定時刻が実行より後なら拒否する。下記の時刻の確認例で検査する。
- 採用理由が前提とした観測対象が外部イベントで変わった場合、旧観測だけでは適用を続けられない。運用から改善、調査への経路と、重大な影響が不明な場合の相談待ちを照合する。
- 同条件の反例が判定を覆す可能性があり、追加実測が予算超過の場合、既存の成功判定は未判定に戻す。既存観測で同じ基準を識別できる場合に限り再判定する。代理指標が同じ方向に動くことだけでは再判定の根拠が不足する。
- 操作結果が不明な場合は失敗から即座に再試行せず、副作用を照合する。再開できる根拠が揃った場合と、揃わず相談待ちにする場合の両方を確認する。

スキーマ検証で、異常系の状態遷移を受理し、再評価や再開を経ずに運用・相談待ち・中断から実行に直接戻る経路を拒否する。構造検査の結果に加えて、異常時の判断条件は仕様同士の意味検査で確認する。外部サービスでの障害注入、代理指標の精度、実測コストは利用環境で別途確認する。

## 実行記録の再現手順

1. 任意の方法でJSONを読み取る。同じオブジェクト内の重複キー、JSONで認められない数値表記は拒否する。
2. [実行記録スキーマ](../schemas/run.schema.json)を Draft 2020-12 として適用し、日時形式も検査する。正常例を受理し、日付のみやオフセットのない日時を拒否することを先に確認する。環境の能力不足で確認できない項目は未検証とする。
3. 構造を確認した記録を対象に、[実行契約](../spec/workflow.md)と[意思決定・証拠の規約](../spec/protocols.md)に沿って下表を再現する。各反例は条件を満たす例の複製から作り、一度に対象の条件だけを変える。日時はオフセットを考慮し、桁数や大文字・小文字の違いで判定を変えない。うるう秒の比較に対応できない場合は原記録を保全し、当該項目を未検証とする。
4. 対象の版、確認した条件、期待結果と実際の結果、未検証項目を記録する。権限の範囲、証拠の真正性、因果関係は意味検査で確認する。案件固有の情報はリポジトリ外で扱う。

| 確認対象 | 入力の変え方 | 期待結果 |
| --- | --- | --- |
| JSONの読み取り | キーを同じオブジェクト内で重複させる。別のオブジェクトでは同名を使う | 前者のみ拒否 |
| 履歴 | 隣接する遷移の前後状態を食い違わせる。開始状態または末尾の現在状態を変える | 不整合を検出 |
| 時刻順 | 同じ時点を異なるオフセットや小文字で表す。その後、小数秒の差だけで順序を逆転させる | 同時刻の表記違いを受理し、逆転を検出 |
| ID | 証拠・判断・同じ判断内の候補のIDを重ねる。選択先、遷移やレビューの参照先を消す | 重複と参照切れを検出。模擬記録でも照合 |
| 版 | Goal・Context・合意を更新し旧版を保存する。旧版を削除、重複させるか、引継ぎを旧版に戻す | 過去の判断は保存された旧版を参照できる。欠落や重複、現行版と一致しない引継ぎを検出 |
| 実行可 | 実運用の実行遷移から判断IDを外す。参照した判断を保留にするか、その確定を実行後に移す | 実行の根拠不足を検出 |
| 合意の時刻 | 実行を発効・期限・撤回の直前、同時、直後に動かす。旧版の発効を期限より後にする | 発効と期限の境界は含む。撤回の境界以降と発効・期限の矛盾を拒否 |
| 測定計画 | 実行後に新しい計画を確定し、判断の参照を旧版、新版、未指定に切り替える。版IDを重ねる | 事前確定した旧版だけを受理。複数版時の参照欠落と重複を検出。旧形式の版なし単一計画も受理 |
| 証拠 | 実行判断の根拠を模擬だけにするか、資料・実測の取得を判断確定後に移す | 根拠不足を検出。確定時刻のない旧記録は実行時点を検査上の上限とする |
| 相互レビュー | 重要な判断でレビューを未実施にし、Context付きレビューを責任AIと同一企業にするか、実行可確定後にしか根拠がない状態にする | 各条件の不足を検出 |

高コストで評価を保留する反例では、成功条件を「閾値以上」として、根拠が支持する値の範囲を変える。下限が閾値と等しい場合は条件充足、上限が閾値と等しく下限がそれ未満なら未判定、上限が閾値より低ければ条件未達となる。未判定で実測が予算を超える場合は、暫定措置と評価を再開する条件を分けて引き継ぐ。費用だけが下がった反例では、権限や判定基準の有効性も再確認する。

複数条件の回帰確認では、2条件のうち一方を未判定に固定し、他方を充足・未達・未判定に変える。「すべて必須」では順に未判定・未達・未判定、「いずれかで可」では充足・未判定・未判定となる。条件の順序を入れ替えても結果は同じ。総合判定が確定した場合も、証拠不足だった個別条件と継続制約を記録できることを確認する。

### 同じ入力で再検証する

[確認データ](validation-cases.json)の各事例について、`基準` のファイルを新しく複製する。`前提` がある場合は同名の `共通変更` を先に適用し、次に事例の `変更` を適用する。変更の配列は標準のJSON Patch（RFC 6902）。`構造` はJSON Schemaの期待結果、`意味` は記載がある場合の規範上の期待結果。両者を個別に照合する。

合意の境界事例では実行時刻を固定し、発効・期限・撤回の各時刻を個別に動かす。発効と期限は境界を含み、撤回と同時刻の実行は適合しない。JSON Schemaが受理した場合でも、判断IDの照合と時刻比較を行い、意味検査の期待結果と比較する。

条件ごとの評価を照合する際は、集約の前に条件IDを入れ子全体から列挙し、重複、判定の欠落、計画外の判定、根拠の参照切れを確認する。いずれもスキーマの構造検査では適合する反例を用意し、意味検査で区別する。

## 大元の目的まで通した比較

[大元の目的の検証](../spec/goal-validation.md)に沿って、小規模な試行の結果を、工程完了で判断する場合と事業成果で判断する場合で比較する。着手前に必須条件を固定し、工程の結果は両方で同じに保つ。対象者への成果、行動で示された需要、総費用を含む採算のいずれかを一つずつ未達にする。別の例では必須の観測を一つ隠す。一定の成果が再現する例も含める。

必須条件の未達では拡大を見送り、観測の欠落では拡大判断を保留し、条件が再現した例では限定拡大を検討できることを確認する。成果を判定した後に、次の投資上限と権限を照合する。評価の結果には、判定が変わった根拠、避けられる支出、確認に追加で要した負担を記録する。

俯瞰から始められるかを確認するには、同じ局所的な不備を残したまま、事業判断を左右する制約だけを切り替える。需要が未確認なら需要を確かめる。需要と顧客成果が確認され、提供能力が制約なら、提供能力を見極める。局所的な不備の影響が両方の判断に及ばなければ保留し、観測後に全体を見直す。

試行順序を比較するときは、同じ費用・所要時間・観測結果を使い、順次案と並行案で次の投資判断に至るまでの費用と日数を記録する。先行する必須条件の未達が確定した例では、後続の試行に着手せず費用を抑えられるかを確認する。各条件が充足する例では、期限の余裕を変え、妥当な順次案が機会を逃す場合と、並行案で機会を維持できる場合を確認する。観測が未判定なら、その結果を未達に置き換えず、追加確認と待つ費用を比較する。

### 事業判断を同じ条件で比較する

次の値は判断の境界を比較するための合成値。実際の案件の入力・成果は各案件で扱う。

| 共通の入力 | 値 |
| --- | --- |
| 試行A（先に確認する必須条件） | 費用1、日数2 |
| 試行B（独立して開始できる必須条件） | 費用3、日数4 |
| 中断費用 | 並行で着手した試行Bの費用3は回収できない |
| 投資の前提 | A・Bと他の事前条件がすべて充足し、提供の機会が残っていること |

順次案はAの充足を確認してからBを始める。並行案は両方を同時に始める。次の期待結果を照合する。

| 観測・提供期限 | 順次案 | 並行案 |
| --- | --- | --- |
| Aが未達 | 2日・費用1で見送り | 2日・費用4で見送り |
| A・B充足、期限6日 | 6日・費用4で限定前進の候補 | 4日・費用4で限定前進の候補 |
| A・B充足、期限5日 | 5日で機会を失う。費用は中断条件に従う | 4日・費用4で限定前進の候補 |
| Aが未判定、Bが充足 | 拡大を保留し、Bは未着手 | Bを観測しても拡大を保留 |

いずれの案でも、作業の完了だけで投資を承認しない。費用の回収条件や試行間の依存関係が異なる場合は、同じ条件で両案を再計算する。

比較の際は、後で判明する事業成果をいったん伏せ、各手順の判断とその時点の根拠を記録する。片方の手順だけが観測費用を払う場合、他方は同じ観測を使えない。事後に同じ観測を開示し、早期の見送りで節約した費用と、後から判明した提供機会・顧客成果の双方を評価する。比較した片方の成果が推定にとどまる場合は、その仮定を変えて判断が逆転するか確認する。

初回と次の対象を比較し、同じ顧客成果の基準を適用する。次の対象でも基準、採算、提供能力が満たされれば限定前進の候補。需要と採算を維持しても提供能力だけが不足する例では、受付上限や提供方法の見直しを検討する。顧客成果と提供能力を維持しても、獲得・提供・再作業の全費用で採算が崩れる例では拡大を見送る。初回しか観測できない例では、再現性を未判定にする。

採算悪化からの回復を比較するときは、既存の成果基準を固定し、現状維持、価格変更、提供範囲の変更、新規受付の停止を同じ期間で比べる。値上げで採算が改善しても需要が基準未達の例と、範囲を狭めて採算は改善しても顧客成果が基準未達の例を含める。顧客成果・需要・採算の基準を満たし、提供能力と既存顧客への約束を守れる案を、費用と期限を限った再試行の候補にする。仮定に依存する条件は次の観測で確認する。

対象を絞っても元の対象者への約束を守れる案と、採算が改善しても合意済みの対象者を取り残す案を比べる。前者は他の条件も満たせば再試行候補とし、後者は人間の合意を要する。新規受付の停止は需要・採算の基準の未達で除外せず、残る顧客対応費用と再試行で増える損失を比較するために使う。

再試行の比較では、利益の基準を満たしても、入金前の支出により既存顧客に必要な資金が不足する反例を使う。下振れ時の先行支出が確保済み資金を除いた上限と等しい案は、他の条件も満たせば候補に残る。上限を超える案は、支出後に入金されて黒字に戻る見込みがあっても、その時点で約束を守れないなら縮小・停止を検討する。

提供方法を変える場合は、処理できる件数、全費用、受付者のうち元の成果に達した人数を同じ期間で比べる。処理能力と採算が改善しても成果が基準を下回る例では、変更案を再試行候補から外す。必要な支援を残す別案も比較し、顧客成果と他の必須条件を満たせるなら、限定再試行の候補にする。

### 追加観測と提供機会の比較

- 試行に費用3・日数3、残予算5・残日数5とする。追加観測の費用・日数がともに2なら観測後も試行できる。どちらかを3にすると、観測が好ましい結果でも該当する上限を超える。
- 誤って見送る損失と誤って着手する損失を分ける。観測の費用と精度を固定し、片方の損失だけを変えて、即時試行・追加観測・停止のどの案が優位になるかを確認する。予算や既存顧客への約束を破る案は比較の前に除外する。
- 比較用に、保持する機会の期待価値を5、直接費を1、他の顧客への影響を同じ尺度で2とすると、保持の純価値は2。影響が6なら純価値はマイナス2になり、枠を解放する方がよい。既存の約束と競合する場合は、純価値にかかわらず約束を優先する。共通尺度を置けないときは、顧客に起きる変化と採算を個別に比較する。

顧客層を限定する案は、変更前の対象に対する成果も併記する。全体では成果基準を満たすが、事前に必須とした顧客層で下回る事例を作る。対象限定による見かけ上の改善、提供方法の変更で両方の層に成果が届く場合、成果は届いても提供工数の上限を超す場合を比較する。

提供枠の保持は、費用が上限と等しい場合も、失効時刻より前で他の条件を満たせば候補に残る。上限を超える場合や失効時刻に達した場合は、その保持条件での更新を見送る。保持と解放の純価値が同じ場合は、取り消しやすさと顧客への影響を比較し、優劣が決まらなければ同等と記録する。

誤判定の比較例として、好条件の確率を半分、観測の感度・特異度を各80%、観測費用と成功時の遅延損失を各1、誤って着手した損失を6とする。観測が肯定的な場合だけ着手する。遅延損失は好条件で着手する場合の価値から差し引く。成功の価値を V とすると、観測案の期待純価値は −1＋0.4×(V−1)−0.1×6、即時試行案は 0.5×V−0.5×6。V を8から16に変えると、観測案と即時試行案の期待純価値はそれぞれ1.2対1、4.4対5となる。採用案が変わることを確認する。

### 提供能力と継続需要の比較

提供能力を改善する案と受付を絞る案を比べるときは、当初の対象者を共通の母数とする。受付を絞った案の採算が改善しても、対象者に届いた成果が必須基準を下回る場合を確認する。提供能力を改善する案についても、改善の費用と、改善が間に合わず顧客成果を失う場合を比較する。

待ち時間が異なる案は、各案で条件を提示した対象を共通の母数とする。申込み後に待ち時間を理由とする取消が発生する反例を作り、残った申込者だけで計算した率が需要基準を満たしても、元の対象に対する有効な申込みの率では未達になることを確かめる。取消を状況不明に置き換え、その全件が有効な場合と無効な場合で判定が変われば保留する。提供を早める案は、需要に加え、期限内に届く成果、追加工数を含む総費用、既存の約束を守れる提供能力も照合する。

提供余力の確認では、需要、作業量、期間全体の能力を固定し、既存顧客の対応と新規の提供が同じ期限前に重なる場合を作る。既存の約束に必要な能力を各時間枠で差し引き、受付制限、増員が期限後になる案、同じ増員を期限前に確保できる案で、期限内の顧客成果、総費用、採算を比較する。期限後に余裕がある案でも、その余裕で期限前の不足を埋められないことを確かめる。

同じ提供期限・需要・成果基準を使い、既存顧客の再作業負荷を通常時から一段ずつ増やす。受付を絞る案と、期限前に予備の担当者や設備を確保する案を比べる。余力の確保費と再作業費を総費用に含め、余力で成果を維持できる場合と、余力を使い切って成果基準を下回る場合の境界を確認する。

代替能力の比較では、同じ需要・顧客期限・既存の約束を与え、常時確保と都度調達を比べる。調達が間に合う条件では両案の成果と費用を比較し、負荷増加と同時に代替先も不足する条件では、総費用が低くても成果基準を下回る案を除外する。調達可能性が未確認なら、確保済みの能力だけで提供できる受付範囲を確認する。

提供方法の変更を比べるときは、価格、対象、成果基準をそろえ、同じ期間の初回申込みと、同じ更新機会での継続を別々に測る。初回申込みと提供能力が維持されても、継続の減少によって元の対象に届く成果や全費用を含む採算が基準を下回る場合を確かめる。更新時期に達していない場合は未観測とし、継続を確認できる範囲で試行する。

一部を切り替える案は、現行維持と同じ対象・需要を置き、更新を観測できる時期と、それまでの両方式の運用費を比較する。更新が基準を下回る場合を加え、試行対象を全員戻せる案と、試行対象の一部しか約束した期限内に戻せない案を作る。後者は観測人数が多くても試行範囲を絞る。両方式の運用費が上限を超える場合は、維持案と試行の見送りを比較する。

同時に試行できる人数を固定し、現行維持、同じ対象の観測延長、試行を終えてから別の対象を観測する案を比べる。対象間の再現性が判断条件の場合、同じ対象の更新回数を増やしても判定は保留になることを確かめる。別の対象で必要な証拠が得られる案も、既存の約束、復帰能力、並行運用費、意思決定の期限を満たす場合にだけ候補に残す。

別の時期・対象で成果が下がった場合は、同じ時期の現行方式と当初と同じ属性の対象での観測を追加する。両方式と両対象で成果が下がる場合と、新しい対象の変更方式でだけ現行方式に対する改善が消える場合を比べる。原因の候補に応じて現行維持と提供方法の限定修正を比較し、需要、総費用、提供能力と成果基準も照合する。比較の観測を欠く場合は原因を未判定とする。

### 外部手段と提供縮小の比較

外部手段に案内する案は、元の対象全体を母数として、案内、受入れ、利用、期限内の成果を順に照合する。同じ人数を案内しても、受入枠や顧客負担によって成果基準を下回る場合と、基準を満たす場合を比べる。運営側の費用が下がっても顧客負担が増える例を入れ、未観測の成果によって判断が変わる場合は保留する。

全件提供、補完支援への縮小、提供終了を、同じ対象と期間で比べる。縮小後も必須の顧客層に成果が届く条件を保ち、残る固定費や移行費を動かして採算が逆転する境界を確認する。提供終了で費用を抑えられても、必須の顧客層が成果を得られない場合は未達を記録する。

再計算用の合成値として、共通の対象10人のうち必須の層を2人とし、同じ期間に両者とも全員へ成果を届けることを基準にする。現行維持は収入20、総費用18、補完支援は収入12、提供の変動費4、移行費2とする。補完支援に残る固定費を3、4、5にすると、補完支援の利益は順に3、2、1となり、現行維持の利益2との優劣が固定費4を境に変わる。固定費4では採算を同等と記録し、必須の層への成果、提供能力、移行負担を比べる。これらでも優劣が決まらなければ、同等と記録する。補完支援の収入と総費用が等しくなる固定費は6。外部の受入枠を8人、自社の補完枠を2人とし、提供終了では費用を抑えられても必須の2人に成果が届かないとする。補完枠を1人に減らす反例では、固定費が3でも顧客成果の基準は未達となる。

## 入口から中断・再開までの通し検証

READMEから始め、対象者や成果が未定の依頼を入力する。判断を最も変える質問と回答、その出典と確認時点を準備メモに残す。元の会話を渡さず、開始遷移の根拠IDから証拠台帳の出典をたどり、準備メモの未確定事項と開始判断の根拠を復元できるか確認する。根拠IDが解決できない場合や出典を開けない場合は未確認と記録する。対象・成果基準・権限が揃った時点で開始判定を記録し、現行維持と改善案を、同じ対象・期限・予算で比べる。需要・成果・総費用・提供能力のうち判断を変える証拠を一つ取り除き、実行可に進まないことを確認する。

不足する証拠を調べている途中で中断し、最後の完了操作、未確定の副作用、入力の版、次手、責任者、復帰先と事前条件を渡す。元の会話を使わずに引継ぎから再開し、完了済みの操作を繰り返さず、記録した次手に戻れるかを確認する。同じ引継ぎで合意の版を変えた場合は、影響の再評価を経るまで旧判断で実行しないことを確かめる。

再開の比較では、対象・需要・合意版を固定し、試行に必要な残予算と提供期限をそれぞれ必要量と同じ値、その直下にする。両方を満たす場合は他の事前条件も照合して復帰先へ戻る。一方が不足する場合は旧判断による試行を保留し、現行維持や範囲を変更した案の成果・総費用・提供能力を、許可済みの資料で比較できることを確認する。

## 過去の判断と測定方法の比較

過去の判断を再現する場合は、判断時点までの資料だけを渡す場合と、検索結果の要約に事後の成果が混ざる場合を比べる。前者は資料の版と判断を記録してから結果を開示し、後者は事後検討と記録する。開示後に判断を更新する場合は、当初の判断を保存し、どの新しい観測で評価が変わったかを示す。

測定方法を変えた後の観測値を12、旧方式の成果基準を9以上とする。両方式で同じ対象を測った記録から、新方式が旧方式より1〜2高いと見積もれば、旧方式相当は10〜11で基準を満たす。差の範囲が1〜4なら旧方式相当は8〜11となり、基準をまたぐため判定を保留する。両方式の観測が別の顧客層に限られる場合は、対象の違いを埋める根拠があるか別途確認する。

必須の顧客層の新方式の観測値を11とする。他の層で得た差1〜2を当てはめると旧方式相当は9〜10になるが、この層にも適用できる根拠が得られるまで判定を保留する。この層を両方式で測り、差が3〜4と分かれば、旧方式相当は7〜8となり基準未達と判定する。

## 再開時の予算・提供枠・期限

「再開時照合」を省いた従来の記録と、全項目を記入した記録を形式検査で受理する。項目を一つ欠く記録や日時形式が不正な記録は拒否する。必要費用と残予算、完了見込と提供期限がそれぞれ等しい場合と、いずれかが上限を超える場合を意味検査で比較する。予算不足・期限超過でも「復帰」と記録した例は、形式検査で受理されても意味検査で不適合とする。

同じ残予算または提供枠を参照する二つの作業を、照合後に再開する例を作る。個別には足りても合計では不足する場合は、両方の復帰判定をそのまま使わず、既存の約束を優先して残量を再計算する。合計と残量が等しい場合は、割当てが確保され、他の事前条件を満たせば両方を実行候補とする。

同じ枠の失効について、着手前に失効した場合、着手後に結果が不明な場合、取消が反映された場合を比べる。期限切れだけで使用状況を判断せず、確認した未使用分だけを再割当てする。未使用を確認できないまま顧客の期限が近づく場合は、別枠と受付制限を、既存の約束、提供できる成果、費用で照合する。

同じ需要と成果基準の下で、新証拠により重要な判断の推奨案が変わる例を作る。新案が成果・総費用・提供能力の条件を満たしても、旧レビューが新案の主要な前提を扱っていなければ、変更の影響を受ける必須レビューが済むまで実行を保留する。変更に関係しない指摘は出典をたどれることを確かめ、許可済みの独立した調査は続けられることを確認する。

レビューが対立する例では、期限までに必要な提供能力を満たすという見積もりに対し、同じ枠が二重に数えられているという反対意見を用意する。実際の割当てを照合し、反対意見の採用・見送り・保留の理由と、その根拠を裁定からたどれることを確認する。元の指摘と照合資料のどちらかが欠けた場合は、採否を記録できていても根拠を再確認できないと判定する。

複数の指摘が使う証拠のうち、提供能力だけが訂正される例を作る。費用の観測と基準は同じ値に保ち、訂正前は提供能力が必要量を満たし、訂正後は下回るようにする。旧裁定の参照先から当時の判断を再現し、訂正後の証拠から提供可否の裁定を再評価する。費用の裁定は訂正箇所に依存しないことを確認して引き継ぐ。

訂正元の照合では、複数回の訂正を元の証拠までたどる。参照切れと、取得が同時刻でも循環する記録は、構造検査に適合しても意味検査で不適合とする。取得時刻が逆転した参照も不適合とする。訂正元の台帳行は残っていても原資料だけ取得できない場合は、旧裁定の再現性と訂正後の証拠で行う今後の判断を個別に評価する。

同じ証拠の同じ項目に対して、訂正元を共有する二つの訂正を用意する。元資料、対象と時期が一致し、どちらを採用するかの根拠が得られない状態で、現行の受付量、受付上限の引下げ、受付停止を比較する。顧客成果の基準、有効な需要、既存の約束と停止後にも残る費用を共通にし、両方の訂正で期限内に提供できる数量と全費用を案ごとに照合する。現行量の可否だけが割れる場合は現行量での受付を保留し、両方で基準を満たす受付上限を候補に残す。その範囲でも条件を満たさない場合は新規受付停止を候補とする。訂正の取得順を逆にしても結論が変わらず、一次資料で訂正が確定すれば既存の基準で再判定できることを確かめる。

新規受付を止めても既存顧客に配分できる能力が足りない条件で、代替提供、期限の再合意、引継ぎ、返金を比較する。同じ顧客、元の成果基準と期限で、提供可能な人数、需要が続く人数、顧客負担を含む費用を照合する。代替能力が期限内に確保できる場合と、期限変更への同意や引継ぎ先の受入れが未確認の場合を比べる。返金だけが完了したケースでは、金銭面の対応が済んでも顧客成果は別に評価し、期限変更に同意した顧客についても元の期限の実績を保全する。

代替枠が不足する例では、同じ数量と費用で提供できる二つの配分案を作る。一方では、枠を得ない顧客が後日の提供で成果を取り戻せるようにし、他方では取り戻せないようにする。提供件数が同じでも、実際に失われる成果の違いを比較できることを確認する。続けて、契約上の優先条件がある場合と、必要な優先基準が未合意の場合を試し、前者は条件に従い、後者は救済候補と決定期限を添えて相談することを確認する。

個々の復旧が完了しても、同じ期間の費用と期限未達が累積すると判断が変わる例を作る。同じ顧客が複数回影響を受ける入力を使い、影響人数の重複を除いても累積遅延と各回の復旧費用が残ることを確認する。単発の場合と繰り返す場合で、復旧継続・方式変更・受付縮小を同じ需要、成果基準、費用上限で比較し、切替中に約束を守れるかも照合する。

継続者に限れば新方式の成果率が高く見えるが、離脱者を元の母数に戻すと成果率の範囲が基準をまたぐ例を作る。未観測者をすべて達成とした場合でも基準に届かない例と、確認済みの達成だけで基準を満たす例も比べる。成果率の判定と更新需要をそれぞれ記録し、上限・下限のどちらでも費用や提供能力の不足を埋め合わせないことを確認する。

同じ顧客成果が観測された二つの群で、一方を比較対象にした例を作る。比較対象への波及がない場合と、共通の担当者や設備を通じて施策の効果が及ぶ場合を比べる。波及の影響で差がなく見える条件と、逆に差が大きく見える条件を試す。影響を受けない比較先で寄与を判定できる場合と、寄与の幅が投資の基準をまたぎ保留する場合を区別し、需要・全費用・提供能力が同じでも判断が変わることを確かめる。

同じ対象と期間で、提供枠を増やす案と課題の発生を減らす案を比較する。利用数が同じだけ減る二つの反例を用意し、一方は課題の発生を防げた場合、もう一方は利用の障壁によって課題が残った場合とする。発生を防いだ対象と提供後に解決した対象を重複なく数え、未解決、顧客負担を含む全費用、残る需要と提供能力から判断が分かれることを確認する。

転換前後の成果の尺度が異なる例を作る。同じ対象範囲・期間で、維持、転換、並行提供について、それぞれの成果と需要、全費用、提供能力を比較する。新しい成果が大きく見えても既存の義務を満たさない案は実行候補から外し、残る案の優劣が成果の優先順位で変わるときは、合算せずに人間が判断できる形で示す。

同じ成果を複数の施策が報告する例を作り、重複を除いた全体の成果と各施策の寄与を別に照合する。同じ需要・期限で、両方を続ける案と片方を止める案を全費用と提供枠も含めて比較する。片方が他方の前提になっている場合は、成果の重複だけを理由に停止せず、片方を外した場合の成果を裏づけられるか確かめる。
