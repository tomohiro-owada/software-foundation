# Software Foundation自身への適用

Goalは、既存のエージェントが事業の判断・証拠・引継ぎを再現できること。既存7文書を保全し、規範と実行記録を追加する案を選んだ。現状維持では事前条件や再開の検査手順が揃わず、専用エンジンは権限外。比較の結果、規範と記録契約を採用した。実運用での有効性と異なる企業のAIレビューは未確認。PRで人間の判断を求める。

## 形式検証

JSON Schema Draft 2020-12と日時形式検査を有効にする。[適合サンプル](business-run.json)は受理し、[不適合サンプル](invalid-review.json)は重要な判断を必須レビューなしで実行可としたため拒否する。適合サンプルの最初の遷移先を「運用」に変更した場合も拒否する。

## 意味検査

| 検証対象 | 実施した確認 |
| --- | --- |
| 曖昧なGoal | 「見積もりを楽にしたい」から対象と工程を特定する一問を作った |
| Contextから非機能要件 | 一人の週稼働時間と情報管理から上限と外部共有禁止を導いた |
| 代替案と判断根拠 | D1で不作為、手作業、専用ソフトウェアを比較した |
| レビュー対立 | 二つの模擬見解を費用感度と手順適合で比較した |
| 結果とGoal貢献 | 作業完了と利益・時間短縮を個別に判定した |
| 外部変化と再評価 | 料金改定で条件を維持したまま再判定し、予算超過と利益不足を確認した |
| 不明なリスクと権限外 | 外部送信と追加費用を保留し、調査のみ継続する次手を記録した |
| 引継ぎ | 中断からの復帰を履歴で照合し、最新の相談待ちに次手と復帰条件があることを確認した |

再検査時は、履歴の先頭・連続性・時刻順と末尾の現在状態、IDの一意性と参照先、判断時点のGoal・Context・合意版を確認する。実運用の実行遷移は実行可の判断と突き合わせ、必須レビューの企業差、共有権限、各根拠、測定の事前確定、合意の有効期限を確認する。模擬証拠の実測への流用、予算超過、成功条件の事後変更を確認したら適合を保留する。構造検査だけでは参照先、レビューの真正性、測定の妥当性、因果関係を判定できない。

次に人間が判断するのは、重要判断の境界と別企業レビューの利用方法、実事業での人件費および観測条件、既存案件に適用する版。自動監視や実顧客での成功は未検証。
