## 指摘

### 1. 実行記録から準備メモの参照先をたどる欄がない（軽微）

- 対象: `spec/workflow.md:22`、`schemas/run.schema.json`
- 根拠: 仕様は「実行記録から準備メモの参照先をたどれるようにする」と定めている。しかし、スキーマのルート・`Goal`・`Context` のいずれにも、準備メモの参照先を書く欄がない。準備メモは、スキーマのルートの説明に名前が出てくるだけである。`additionalProperties: false` のため、参照先を書けるのは自由記述の欄か証拠台帳に限られる。
- 影響: 通し検証（`examples/validation.md:151`）の「メモの参照先から未確定事項と開始判断の根拠を復元できるか」を、記録の構造に基づいて確かめられない。参照先がどこにあるかは検証者が探すことになる。
- 修正案: ルートまたは `引継ぎ` に任意欄 `準備メモ`（参照先と確認時点）を追加する。あるいは、準備メモを証拠台帳に登録し、開始の遷移の根拠からその ID を参照するという方針を明記する。

### 2. 再開時照合の受理・拒否の事例が確認データに入っていない（軽微）

- 対象: `examples/validation.md:159`、`examples/validation-cases.json`
- 根拠: 手順は、欄を省いた記録と全項目を記入した記録を受理し、項目の欠落と不正な日時を拒否することを求めている。また、予算不足なのに「復帰」と記録した例を意味検査で不適合とすることも求めている。しかし、対応する JSON Patch の事例が確認データにない。上の表は、この場で合成した例で確かめた結果である。
- 影響: 合意の境界や評価の集約と違い、この欄は同じ入力で再検証できない。必要費用と残予算が等しい場合の判定も、検証者によって分かれうる。
- 修正案: 確認データに次の事例を加える。
  - 再開時照合あり（構造は適合）
  - 項目の欠落と日付のみの日時（構造は不適合）
  - 必要費用と残予算が等しく判定が「復帰」（意味も適合）
  - 必要費用が残予算を超えるのに判定が「復帰」（構造は適合、意味は不適合）
