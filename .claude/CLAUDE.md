# Software Foundationの定期レビュー

定期レビューを依頼されたときは、この手順に従う。対象は依頼で指定されたコミットまたは範囲とする。指定がなければローカルの `HEAD` を対象とし、確認したコミットSHAを記録する。未コミットの変更は別扱いとし、対象に含める指示がある場合だけ確認する。

## レビュー手順

1. リポジトリ直下の `README.md`、`spec/`、`foundations/` を読み、Goal、合意済みの制約、現在の判断規範を把握する。前回確認したコミットを特定できる場合は、その後の差分と関連する仕様を優先する。
2. 仕様、JSON Schema、検証手順の整合を確認する。正常系に加え、突発イベント、反例、証拠不足、実測の費用超過、中断からの復帰を調べる。合成の反例は事業や案件に依存しない最小例にする。
3. `examples/validation.md` の再現手順に従い、利用できる手段で構造と判断を検証する。結果には実行した検査、確認した事実、推測、未検証の項目を明記する。
4. 指摘ごとに、対象ファイルと行、根拠、影響、再現条件、修正案を記載する。該当する指摘がなければ、確認した範囲と検証上の限界を記載する。

## 出力と権限

- レビュー結果は、日本語のMarkdownをリポジトリ直下の `.claude/` に直接書き出す。ファイル名は `review-YYYYMMDDTHHMMSSZ-短縮SHA.md` とする。既存ファイルと重なる場合は連番を付け、上書きせず保存する。
- レビュー結果、補足、検証ログを保存する場所は同じ `.claude/` に限る。サブディレクトリや別のディレクトリには出力しない。Gitでの提出は次の手順に従う。チャットの完了通知には保存先と完了状態だけを示す。
- レビュー中のリポジトリは読み取り専用として扱い、この指示書や仕様、コードを編集しない。書き込みが発生する検証は行わない。
- 報告には抽象化して再現できる条件と判断を残す。案件固有の入力、秘密情報、機密データ、外部への共有が許可されていない情報は転記しない。


## レビュー完了後の提出

定期実行の設定または実行側の自動チェックからコミット・プッシュを指示された場合は、その指示を提出工程に適用する。レビュー完了後に、今回作成した `review-*.md` だけを個別のパスでステージし、差分を確認してコミットする。指示された提出先がこのリポジトリであることを確認してからプッシュする。提出時もレビュー結果のパスは `.claude/` 直下とし、既存の変更や補足ログは巻き込まない。PRは別途指示された場合に作成する。

提出の指示がない場合はファイルに保存して完了とする。提出に失敗した場合はファイルを保存したまま、完了通知に保存先と失敗理由を示す。
