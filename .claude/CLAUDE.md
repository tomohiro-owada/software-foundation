# Software Foundationの定期レビュー

定期レビューを依頼されたときは、この手順に従う。対象は依頼で指定されたコミットまたは範囲とする。指定がなければローカルの `HEAD` を対象とし、確認したコミットSHAを記録する。未コミットの変更は別扱いとし、対象に含める指示がある場合だけ確認する。

## レビュー手順

1. リポジトリ直下の `README.md`、`spec/`、`foundations/` を読み、Goal、合意済みの制約、現在の判断規範を把握する。前回確認したコミットを特定できる場合は、その後の差分と関連する仕様を優先する。
2. 仕様、JSON Schema、検証コードの整合を確認する。正常系に加え、突発イベント、反例、証拠不足、実測の費用超過、中断からの復帰を調べる。合成の反例は事業や案件に依存しない最小例にする。
3. 実行環境に必要な依存がある場合は、リポジトリ直下で `python -B validation/check.py` を実行する。結果には、実行した検査、確認した事実、推測、未検証の項目を明記する。欠けた依存は記録する。
4. 指摘ごとに、対象ファイルと行、根拠、影響、再現条件、修正案を記載する。該当する指摘がなければ、確認した範囲と検証上の限界を記載する。

## 出力と権限

- レビュー結果は、日本語のMarkdownをリポジトリ直下の `.claude/` に直接書き出す。ファイル名は `review-YYYYMMDDTHHMMSSZ-短縮SHA.md` とする。既存ファイルと重なる場合は連番を付け、上書きせず保存する。
- レビュー結果、補足、検証ログを保存する場所は同じ `.claude/` に限る。サブディレクトリ、別のディレクトリ、外部サービスには出力しない。チャットの完了通知には保存先と完了状態だけを示す。
- レビュー中のリポジトリは読み取り専用として扱い、この指示書や仕様、コードを編集しない。書き込みが発生する検証、ブランチ切替、コミット、プッシュ、PR作成は行わない。
- 報告には抽象化して再現できる条件と判断を残す。案件固有の入力、秘密情報、機密データ、外部への共有が許可されていない情報は転記しない。
