## 指摘

### 1. 期限5日の行で、順次案の費用が一意に決まらない（中）

- 対象: `examples/validation.md:89-91`、`:100`
- 根拠: 中断費用の行（`:91`）が定めているのは、並行案で着手したBの費用だけである。順次案では、Aが充足した2日目の時点で、Bを始めても完了は6日目になり、期限の5日を超えると予見できる。このとき、Bに着手しない（費用1）のか、着手してから中断する（費用4）のかを決める規則がない。表の「費用は中断条件に従う」が指す条件も定義されていない。`:81` の「妥当な順次案が機会を逃す場合」を合理的な判断と読むなら、Bには着手せず費用1になると推測する。
- 再現条件: 共通の入力のまま、期限5日の行を順次案で計算する。
- 影響: 検証者によって、順次案の費用が1にも4にもなる。順次案と並行案の費用差（3または0）の解釈が変わり、「並行で機会を守る価値」の評価が逆転しうる。
- 修正案: 順次案の規則として、期限内に完了できないと分かった時点では後続の試行に着手しないことを明記する。そのうえで、表の値を「2日で機会喪失を確定し、費用1」のように具体的に書く。期限の境界（期限日の完了を含むかどうか）も表に明記する。

### 2. 未判定の行に日数と費用がない（軽微）

- 対象: `examples/validation.md:101`
- 根拠: 他の行は日数と費用を示しているが、この行は判断しか示していない。共通の入力には、Aが未判定に終わる場合の観測日数も定められていない。
- 影響: `:81` が求める「追加確認と待つ費用を比較する」を、同じ入力で再現できない。
- 修正案: 未判定が確定する日数（例: Aの日数2）と、並行案で発生済みの費用4、順次案の費用1を記載する。あわせて、追加確認の費用と日数を合成値として加える。

### 3. 比較表が機械照合用の確認データに含まれていない（軽微）

- 対象: `examples/validation.md:83-107`、`examples/validation-cases.json`
- 根拠: 評価の集約や合意の境界は JSON Patch の事例で照合できる。しかし事業判断の比較は Markdown の表だけで、入力と期待結果を機械で読めない。
- 影響: 改善の前後で、同じ入力に基づく再計算を自動で繰り返せない。
- 修正案: 共通の入力と各行の期待結果を、確認データに別の区分として加える。例えば `事業比較` という配列に、試行・費用・日数・期限・観測と、順次案・並行案それぞれの期待結果（日数、費用、判断）を持たせる。

## 未検証・限界

- 「次の顧客にも提供できるか確かめる」（`spec/goal-validation.md:35-39`）と、事後の成果による比較（`:29-33`）は、仕様同士の整合を読んで確認しただけで、合成値による再計算はしていない。
- 模擬検証で確認できるのは、条件によって判断が変わるかどうかだけで、実事業での効果は確認していない。
